# @arbi/traffic

Implemented shared Node 24 transfer taps, bounded SQLite raw-counter/attempt spool, Linux sysfs collector and optional bounded router snapshot adapter for [#26](https://github.com/gredice/arbi/issues/26). The [edge executable](../../apps/arbi-edge-controller/README.md) and its simulated pod consume the application adapter. [Metering semantics](../../docs/software/device-traffic-metering.md) and [host evidence](../../docs/evidence/device-traffic-metering.md) define coverage and remaining gates.

Build with `pnpm --filter @arbi/traffic build`; portable fixtures with `pnpm --filter @arbi/traffic test`; native Linux loopback comparison with `pnpm --filter @arbi/traffic test:linux` after build. The last command fails on other platforms. Node SQLite is a runtime requirement. Internal dependencies use `workspace:*`; no new pod application or provider dependency exists.

`ApplicationMeter.upload` and `download` wrap real chunk submission/receipt. `submit` observes a callback-based socket submission; `observe` is a best-effort received-buffer tap. Each attempt has its own ID, category, scope, raw timestamps and outcome. Every retry is counted again with optional `retryOf`; it stays in the original category with retries included. Neither a local write callback nor received bytes proves remote application acknowledgement, successful object storage, watching, installation or physical behavior.

`TrafficSpool` takes an explicit file, realm/site/mode/device binding and four capacity bounds. `pending` returns up to 64 terminal raw records and hashes; a prefix can be removed only through `acknowledge({id,contentHash,durable:true})`. The caller must obtain a real durable sink receipt; this library does not fabricate one or implement cloud ingestion. Active attempts remain on disk and become partial `crashed` records on the next single-writer startup. Stop local work before attempting accounting cleanup. Strict upload/download wrappers surface storage failures; socket taps contain those failures and preserve explicit degraded status.

`LinuxInterfaceCollector` reads one explicitly configured interface and a caller-maintained deployment epoch. `RouterCollector` accepts one source-specific report callback, explicit coverage/directions/collection point, a 1–10,000 ms timeout and at most 4 KiB JSON snapshots. The callback must bound its own HTTP response and honor `AbortSignal`; an ignored abort quarantines that outstanding callback so later polls cannot accumulate requests. No vendor protocol, default SIM, endpoint, credential or tariff is assumed. `parseRouterSnapshot` validates the full report shape and exact unsigned values. Configurations and reports belong in private deployment storage.
