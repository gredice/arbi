# Audit completeness coverage

Work record: [#64](https://github.com/gredice/arbi/issues/64); [ADR-0018](../decisions/0018-audit-coverage-and-source-sequences.md). The canonical machine-readable [coverage matrix](audit-coverage.json) lists all 17 HTTP routes and existing edge command/transfer/recovery, commissioning, release/update and disabled recording hooks. Each entry lists actions, required facts, executable scenario files and limits. `src/audit/coverage.test.ts` compares the inventory with the actual HTTP route tree so a new entrypoint cannot silently escape this review.

The matrix distinguishes authorization, intent, admission, grant, signed device/media observation, browser advisory and service outcome. A service timeout is not a measured physical stop; a URL grant is not a download; staged update bytes are not an installed boot; unavailable meters are not zero usage. Direct APIs use the same admission policy as dashboard bridges. An allowed authorization check may commit before a later action transaction fails, but the failed admission cannot leave an executable job or fabricated success.

Cloud job/realtime/live source sequences now advance independently of command sequences and other service instances. Allocations and facts share the registry transaction. Rollback releases reservations; replacement service outcomes carry their own clock identity and retain the original actor and intent. Existing historical gaps remain immutable. Protocol terminal outcomes preserve protocol sequence numbers: those diagnostics describe a selected protocol evidence range, whose holes are not proof that an audit event was lost. Nonterminal and contradictory reports remain separately queryable.

The linked scenarios exercise actual PostgreSQL/SQLite admission and replay, independent connections, required audit/outbox failure, stale/current authority, direct operator/viewer access, configuration commits, synthetic update journals, live/still grants, independent export authorization, privacy redaction, disabled recording and lost receipts. Physical source confirmation and provider instrumentation require separate evidence. The inventory explicitly records those gaps instead of marking a source fixture as end-to-end physical coverage.

Malformed unauthenticated requests, an unavailable ordinary runtime and provider login/logout lifecycle have no fabricated verified human or canonical execution fact. Verified job denials use bounded first-event/count projections; missing required audit prevents sensitive admission. A denial remains a denial when storage cannot record the attempt.
