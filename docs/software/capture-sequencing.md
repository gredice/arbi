# Traceable capture sequence source adapter

This [#53](https://github.com/gredice/arbi/issues/53) adapter consumes the [gimbal model](gimbal-model.md). [ADR-0033](../decisions/0033-traceable-synthetic-capture-sequencing.md) records its boundary. The ordinary pod listener still supports only diagnostics; no camera device or electrical servo is opened.

`CaptureSequencer` accepts an actual locally applied pod configuration and compatibility boundary, trusted current command gate/clock/context, a native `CaptureStore`, the actual `GimbalModel` and a synthetic camera. Its private `arbi.capture-profile/1.0` record binds configuration/calibration/profile revisions, exposure in microseconds, analogue gain, single autofocus and lens range, optional preview and synthetic frame dimensions. The current source adapter limits dimensions to 512 × 512 and payloads to 8 MiB. This is a bounded synthetic profile, not a selected real camera's maximum-resolution specification.

Pass actual `camera.capture` and `camera.gimbal` protocol commands with the same requesting actor/source/correlation/lease. Admission validates the configuration, actor, source, current target epoch, increasing new-command sequence, deadline and lease. A retry with a changed transport message ID/sequence retains the same semantic receipt; changing command/body/profile identity conflicts. Cached result delivery still checks current authority/deadline and raw integrity. Expired requests require authorized result inspection rather than another camera effect.

The sequence is stopped-motion proof → gimbal → fresh settling → camera initialization → approved profile → autofocus → optional preview → still → durable raw receipt. Each camera call has a bounded wall timeout and abort signal, with authority and settling checked before/after. The local clock must advance during settling waits; an overall host wall bound also prevents a frozen clock from extending camera execution. Focus failure, unavailable camera, framing/motion interruption, expired/revoked authority, preview busy, storage full and interrupted writes retain distinct bounded reasons and the last phase.

One coordinator owns a given camera. `acquirePreview()` reserves it explicitly; capture while reserved returns `CAMERA_BUSY`. Release is idempotent and cannot release a subsequent owner. `close()` refuses while busy, and an idle closed owner cannot admit work. Preview is optional after autofocus, and no always-on or WAN media sender exists here.

`CaptureStore` requires a private `arbi-pod-capture-*` directory directly under the OS temporary directory and an exact realm/site/module binding. Native SQLite reserves up to 128 receipts without eviction and limits its database to 8 MiB; raw intents/files have a fixed quota up to 64 MiB, including failed writes. New files have mode 0600 and cannot follow links. Each new PNG gets a unique identity, bounded header/chunk/CRC/inflate validation, digest, fsynced temporary file, atomic rename, directory sync and readback before receipt completion. An exclusive native owner lock releases on actual process death. Existing valid committed images survive a lost final acknowledgement; missing/partial images become failed receipts, and interrupted reservations never redo camera actions. Completed images are verified again on raw delivery/retry. Retention and resumable acknowledged ownership belong to #61.

The private `arbi.raw-capture/1.0` metadata preserves original message/command/correlation/idempotency/source/actor/deadline/lease, resource/job/target, module epoch, declared time/uncertainty, requested/available pose with units/frame/sample/age, gimbal/calibration, focus/preview/profile and runtime/configuration identities. Unavailable pose/time is null; old estimates are stale and never measured. `processing.state=not-processed`, `upload.state=not-uploaded` and `physicalCamera=false` keep subsequent owners and evidence separate. No credentials or free-form exception strings are recorded. See [source and bench evidence](../evidence/capture-sequencing.md).
