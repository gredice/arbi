# Controller-specific update model

This is the [#72](https://github.com/gredice/arbi/issues/72) source adapter, consuming [#71's signed flash model](pico-flash-model.md). [ADR-0031](../decisions/0031-controller-update-owner-interlocks.md) records the boundary. No physical installer is enabled.

`local_model_update_begin` runs in the trusted single C owner. Its command uses the existing local boot/session, seven revision identities, sequence, fence, deadline and recovery generation. `LocalUpdateEvidence` is trusted synthetic evidence, not a wire message or physical certificate. Parked has no authority: `update_safe`, isolated outputs, independent restraint, line clearance and stable power must all be explicitly true, with a different protection owner and sample younger than 100 ms. Active/prepared motion, an existing lease, pending fault, lost link or late owner loop refuses admission. The admitted boot remains locked even after image rejection or reconnect. Only reset removes that lock, leaving configuration, reference and plans unavailable.

`ControllerPicoUpdateModel` accepts an already constructed `SignedPicoFlashModel`, trusted `owner.read/reserve` callbacks, a provisioned synthetic edge identity and transfer key, and a local monotonic clock. It has no CLI/HTTP/serial entrypoint. `stage`, `activate`, `confirm` and `tick` consume the existing cryptographic and native journal implementation. `owner.reserve` must atomically perform the actual owner reservation before returning true. Named Node tests use a synthetic owner fixture; C host tests independently invoke the actual C reservation. Neither demonstrates a connected MCU installer.

The private `arbi.controller-update/1.0` inventory provides verified host slot and staged build/digest, phase/reason, current epoch, configuration digest and local trial deadline. `firmwareExecuted=false`, `physicalInstallationEnabled=false`, `remoteActivationSupported=false`, `requiresLocalService=true` and `localServiceReason=PICO_PHYSICAL_RECOVERY_UNPROVED` are unconditional. Confirmation never clears commissioning reconciliation or restores queued motion. No canonical device boot receipt is fabricated from a host slot.

First physical provisioning and local rescue remain unavailable adapters. Their future procedure must identify the board, trusted signing material, firmware/source identity, protected configuration, BOOTSEL/SWD access, independent output isolation/restraint and post-boot compatibility/reference reconciliation. Real trial or rescue tests may only follow the reviewed independent protection procedure. The [acceptance matrix](../evidence/controller-update-model.md) keeps unavailable timing/equipment explicit.
