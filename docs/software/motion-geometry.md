# Revision-bound motion geometry

The simulator's `motionProfile`, `poseToCounts` and `countsToPose` implement the same declared model as `motion.c` in the control-cabinet application. [ADR-0025](../decisions/0025-revision-bound-motion-model.md) records the boundary. The simulator validates the shared configuration before deriving the profile; host preparation emits the corresponding C fixture. Ordinary firmware never links that fixture or advertises motion readiness.

For each axis, millimetres per commanded microstep equal `2π × radiusMm / (fullStepsPerTurn × microsteps)`. Cable payout is Euclidean anchor distance plus the calibration offset. Absolute count is `homeSteps + direction × roundAway((payoutMm − homeCableMm) / mmPerStep)`. Ties round away from zero in both languages. Home offsets are explicit references, not evidence that a home switch was observed. The synthetic fixture uses different radii, alternating polarities and different home references to exercise all four axes.

Configuration digest, site, hardware digest, calibration revision, geometry revision, site-frame revision and model binding digest are copied into every model request. The binding includes the entire configuration and all mechanics, including travel/rate limits. Replacing a drum/line/configuration/calibration changes that identity. Reconciliation at admission, start, every commanded observation and completion inhibits stale intent; readiness must be deliberately restored. Profile ownership is local and trusted. This API does not authenticate a sender or accept raw network configuration.

`motion_restore` initializes a simulated reference and a copied validated profile. `motion_admit` rejects concurrent intent and creates one owned finite pulse plan. `motion_begin` supplies a separate immutable copy to its consumer. `motion_observe_commanded` permits only monotonic progress within the admitted absolute target counts and rechecks travel/workspace/identity. `motion_complete` settles the finite commanded target once. Reset, invalid profile replacement and revision mismatch discard queued intent; no old capture or move is replayed. The API is single-owner and has no interrupt, transport, GPIO or physical stop handler.

The planner validates at most 514 pulse words before making a segment available. Inverse geometry checks every quantized command against the rectangular site workspace, cable/count travel and sphere residuals. Endpoint-average estimated speed and nominal duration are bounded. Requested acceleration feeds the discrete step-rate envelope, with explicit per-axis ceilings; changing radii are not treated as calibrated mechanics. Physical Cartesian velocity/acceleration, continuous installed position and tension are not established by these estimates.

`motion_report` contains commanded absolute counts, estimated cable millimetres and estimated site pose with configuration/calibration/model provenance. Inhibition marks retained estimates stale; an uninitialized or invalid profile marks them unavailable. Measured position and tension remain null/unavailable; `physicalAcceptance` remains false. No absent tension channel passes a protection check. Estimated pose selects the branch below the rectangular anchor plane and permits at most four microsteps of cable residual. This accounts for discrete commands only, not sag, stretch, helix, loading, sensor uncertainty or mechanical stopping.
