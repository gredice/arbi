# Media audit software evidence

Scope: [#56](https://github.com/gredice/arbi/issues/56), [ADR-0015](../decisions/0015-media-audit-visibility.md). This records isolated software/native-host behavior, with no installed camera, relay, carrier or human viewing measurement.

Native PostgreSQL tests create two independently authorized viewers with one producer, ingest signed immutable accounting windows, then ingest signed delivery summaries. Each viewer retains its original actor/history/downstream interval and references the same upstream window; the garden usage reader counts that window once. Cross-viewer references fail. A duplicate signed report is acknowledged without another audit or usage row. Explicit end and abandoned-viewer timeout preserve partial coverage, a duration upper bound, null playback duration and unobserved remote stop.

Still fixtures use the actual Blob signing SDK against an owned loopback object/signing service. They check required grant/audit state before GET signing, independent human view/download grants, URL replay after revocation until expiry, signing failure with original-grant correlation, and no invented delivery event from a GET/cache response. Required metadata/audit failure returns no capability and cannot call GET signing. Native SQL checks guard actor changes, deletion and revocation reversal; legacy grants remain unchanged. In-memory source fixtures explicitly opt into test-only schema behavior and do not prove WAL durability; ordinary fsync-off audit is rejected.

Recording contract fixtures cover six future hook purposes, verify current Gredice recording denial even with engineer/update-admin roles, and reject fabricated successful recording/access events. No recording permission or runtime was enabled.
