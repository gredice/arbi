# Cloud operations and restore evidence — 11 October 2026

Scope: [#47](https://github.com/gredice/arbi/issues/47), [ADR-0011](../decisions/0011-cloud-recovery-quarantine.md), [operations contract](../software/cloud-operations.md), Node 24.19.0, pnpm 11.5.2, native PostgreSQL/pg_dump/pg_restore 18.4. Reviewer: Codex, executed checks and source self-review. This is isolated native software evidence, not provider/physical acceptance.

Four source tests reject private configuration/realm/TLS/origin/key mismatches with fixed errors, prove the 64-entry closed log/int32-counter projection excludes private exception text, verify process-boot reset and preserve dependency slots across timeouts, and exercise fail-closed unconfigured HTTP. A stalled probe cannot accumulate overlapping work even if its callback ignores cancellation.

Four native checks (parent plus three scenarios) run in a fresh owned socket-only cluster. The first uses an independent read-only health role with narrow function/SELECT grants, detects an unsafe owner-role connection, denies barrier/receipt writes, self-audits site health, denies viewer access, exposes broker outage/recovery and withholds a prepared result after current session revocation. Provider probes are controlled fixtures, not external provider tests.

The second holds an ordinary application transaction while an owner changes quarantine, demonstrating the shared lock prevents an in-flight admission race. After the transaction commits, the barrier denies later reads and signed job polling. It leaves the pending device result unknown.

The third creates an actual private custom-format pg_dump of paused source admission, rejects changed archive bytes, and restores a different empty database with pg_restore. It checks exact table fingerprints, original command/registry/audit references, a separately signed/verified simulation release-catalog digest and its durable publication reference, 0600 archive/manifest permissions and closed restored PUBLIC privileges. The source contains one active lease and one pending capture with no terminal device report. A SQL failure after recovery staging rolls all recovery/audit/projection changes back. A successful retry retires that lease, suppresses pending delivery, revokes the restored device key, clears receiver/current projections, rotates realtime epoch and admits one explicit policy audit record without inventing execution success. Identical recovery retries return the same receipt; changed digests and receipt mutation fail. The durable audit chain still verifies. Original submissions/signed snapshots stay unavailable, and reapplying the additive migration preserves quarantine.

The local focused native drill passed all four checks in approximately 1.6 seconds; dump/restore/recovery scenario took approximately 236 ms on this development host. These are observations under tiny synthetic data, not production recovery targets. The PostgreSQL server/client tools reside outside the repository, and the launcher removes only its own temporary fixture/archive directories. No credentials, dumps, private keys or real coordinates are committed.

Owning validation includes dashboard lint/typecheck/build, source tests, the full native suite, the full built-app Chromium regression suite, ordinary/branch-preview HTTP checks, documentation links and whitespace. All 50 native database checks passed in approximately 33 seconds, all 75 source checks passed (14 native-only skips), and all 11 built-app Chromium checks passed. Lint/typecheck/build, ordinary/branch-preview HTTP, documentation links and whitespace passed. CI results are recorded in the implementation PR.

Actual Neon/PITR roles and restore branches, Gredice directory state, Ably/relay credential revocation, Vercel deployment churn, private Blob byte recovery, cellular counters, local journal/fence reconciliation and installed hardware RPO/RTO remain unverified. The fixture preserves immutable metadata/references and blocks admission; it does not prove device stopping, provider credential deletion, image-byte backup or carrier billing recovery.
