# Seeded fault workflow software evidence

Scope: [#77](https://github.com/gredice/arbi/issues/77), [ADR-0022](../decisions/0022-seeded-service-fault-workflows.md). Local reviewer: Codex. Setup: Linux x64, Node 24.19.0, pnpm 11.5.2, PostgreSQL 18.4 in a fresh socket-only cluster, private SQLite journals, actual Gredice boundaries, authenticated loopback HTTP Range and real private Blob SDK against the existing isolated HTTP fixture. All signing/identity keys are ephemeral and private.

Seed 77 declares all local virtual fault injection times. Two independent runs return identical semantic traces/digests; seed 78 changes fault timing. The eight local fault cases fail original work and require recovery; retrying the original envelope returns the original outcome and cannot redispatch. Host restart is an explicit close/reopen of actual durable journals; earlier committed job crash tests separately use process termination. A cloud outage rejects continuing manual authority without disabling the local stop path.

Three 70,000-byte actual update payload cases reconcile HTTP response-body bytes with original transfer charges: interrupted prefix resumes after reopening the edge operation journal, a failed Pico canary rolls back and leaves pod/edge untouched, and corrupt content fails digest verification with no installation. Invalid signature admission reads no artifact payload. Each exhausted discretionary allowance still admits a synthetic required-health reservation and denies optional media. This essential reservation proof does not measure an actual health socket or radio transport.

Native cloud tests call actual protected Fetch APIs and persisted services. An unauthorized viewer cannot manipulate; an allowed job retains unknown device outcome when operator revocation prevents polling delivery. Two live viewers receive separate grants for one isolated producer, a third exceeds capacity, a reduced profile policy revokes old grants, an explicit lower-profile request succeeds, and exhaustion stops demand. This adapter exchanges signaling only, so grants and policy ends create no video-delivery observations. Six disabled recording hooks deny before their handlers; existing protocol tests retain reserved lifecycle fixtures.

The real media SDK fixture reads a 123-byte synthetic PNG PUT twice. The retry is rejected after reading its body; actual application upload bytes are 246, verified object size is 123, and idempotent completion retains one image and one successful completion. HTTP headers, TLS, carrier bytes and private media contents are excluded from this accounting layer and trace.

No physical GPIO timing, motor behavior, camera capture quality, radio/billing measurement, installed updater or field gate is validated. The [representative semantic trace](fault-workflow-traces.json) uses only synthetic identities; source clock/boot and random event identifiers remain in private original journals. Exact-head CI and reviewed software revision are recorded on the issue PR.

Local validation: the 12-scenario local workflow suite passes three independent runs (two matching seed 77 traces plus seed 78); all 70 native PostgreSQL checks pass, including protected manipulation/viewing/recording scenarios; 18 media/fault source checks pass with two native-only skips. Edge build/lint and dashboard lint pass; 294 documentation links and whitespace pass. The existing #75 browser and HTTP regression evidence remains recorded by its merged PR; this test-only workflow change adds no public endpoint or physical activation.
