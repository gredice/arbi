# Audit-completeness software evidence

Scope: [#64](https://github.com/gredice/arbi/issues/64), [ADR-0018](../decisions/0018-audit-coverage-and-source-sequences.md), [coverage matrix](../software/audit-coverage.json). The matrix binds all 17 HTTP routes and existing internal action families to executable evidence and explicit observer limits. Inventory coverage alone is not behavioral or physical proof.

Native PostgreSQL 18.4 scenarios use owned isolated Unix sockets, fsync and synchronous acknowledgement, independent connections, ephemeral signed identity/device credentials, private temporary SQLite spools and synthetic site data. Direct operator submission produces one executable command envelope and an attributable intent/authorization chain. A direct viewer submission returns 403, records the verified viewer denial and adds no job. Injected outbox failure returns 503 and adds no executable job. Retried submissions, lost receipts and competing connections preserve immutable command identity and canonical event history. Required storage failures roll back audit/outbox/jobs as one admission; device reports cannot fabricate service/physical completion.

The new regression queries inspect every cloud job-service stream across command allocations, concurrent source epochs, SQL rollback and service replacement. Fresh streams are dense and their canonical gap diagnostics are empty. Replacement live-service closure retains the initiating actor and intent while using the replacement service's own source identity/clock. Existing source history is never renumbered. Original offline source gaps and selected terminal protocol evidence remain explicit; the diagnostic reconnect scenario retains a missing sequence rather than inventing an observation.

The native stage also runs independent media access, scoped audit export/retention, current revocation, telemetry, usage/budget policy, realtime recovery, operations recovery and privacy fixtures. Source-only recording tests deny all six reserved operations. Commissioning and update-journal fixtures retain the original actor/configuration/release and distinguish simulated device acknowledgement, observed boot and interrupted unknown outcomes. Actual installation wiring remains separately gated.

Public evidence contains scenario descriptions and bounded counts, with no ephemeral credentials, private keys, access URLs, raw request/media bytes or real site coordinates. Tests keep these private and export only closed fields/pseudonyms. Missing observers include provider login/logout lifecycle, real first-frame/download/playback/relay billing, physical stop/configuration/calibration/capture confirmation and installed MCU/Linux update recovery. These cannot be established by a manifest, a dense hash chain or an isolated fixture. Current gates remain in the matrix and subsystem issue evidence.

Run conditions: Linux x64, Node 24.19.0, pnpm 11.5.2, PostgreSQL 18.4, synthetic identities/resources, no real deployment or live-device connection. Local verification passed: 88 dashboard source checks (15 native-only skips), 67 native checks, 17 Chromium checks, 10 affected audit/recording source checks, production build/lint, ordinary/preview HTTP probes and documentation links. Unchanged commissioning/update contract evidence is also recorded at the previously merged #46 baseline; those physical observers remain unavailable. The issue PR records exact-head CI and automated review.
