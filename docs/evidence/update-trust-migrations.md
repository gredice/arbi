# Signing-trust and migration software evidence

Scope: [#74](https://github.com/gredice/arbi/issues/74), [ADR-0019](../decisions/0019-isolated-trust-and-migration-recovery.md). Four executable isolated security scenarios use Node 24.19.0, pnpm 11.5.2, Linux x64, actual private SQLite and synthetic module/site data. Ephemeral root/release private keys exist only in test process memory; child-process arguments contain public root data and synthetic artifact bytes.

The persisted test device accepts a planned old/new key overlap, rejects corrupted/wrong-key/revoked artifacts, retains revocation across restart, requires a reviewed-reference checkpoint after missed rotation windows, rejects an untrusted checkpoint, and rejects clock rollback across restart. Unknown credential fields/private root keys are rejected. Diagnostics suppress unexpected callback exception text. Known ephemeral private PKCS8 bytes and private-key markers are absent from the tested artifact, public policies, private trust file and diagnostic JSON. This fixture inspection does not claim inspection of a deployed firmware/web image or production key custody.

The planner accepts the existing compatible edge-first bridge, rejects a pico-first incompatible state and forged manifest, blocks unsafe prior-release restoration after a security-floor increase, and accepts a signed compatible replacement set at the floor. Security version comes from the root-bound release digest and is independent of build version. The source fixture demonstrates ordering/recovery arithmetic, not observed mixed-device installation.

The migration scenario uses representative persisted voltage/speed limits and revisions. A pre-commit failure retains active prior data; an acknowledged prepared marker survives an interrupted response/reopen; apply changes the actual SQLite snapshot; restoring the declared prior release returns the exact prior data. Unknown transformation enters recovery-required. A higher security floor blocks downgrade and preserves both current and prior snapshots. A separate migration process exits before SQLite commit, then reopening exposes the prepared marker and unchanged prior data. Another process-termination test verifies journal rollback directly. No motion/update actuator or live-device endpoint is involved.

Local build, lint, four security scenarios, 33 existing release/update/audit contract checks, the packaging-helper check, the audit coverage guard and 285 documentation link checks pass. The issue PR records the tested revision, exact-head CI and review. Local verification reviewer: Codex. Missing evidence: production offline/protected signing custody, installed firmware/web artifact inspection, physical root provisioning and recovery review, OTP/security hardware behavior, representative installed MCU/Linux boot rollback and active commissioning configuration migration. These remain separate subsystem gates; no qualified physical acceptance is claimed.
