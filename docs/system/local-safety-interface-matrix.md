# Local safety interface matrix

## Status and use

This requirements register implements [ADR-0006](../decisions/0006-local-safety-authority-and-instrumentation.md). It assigns functional interfaces and evidence owners; it is **not a GPIO allocation, terminal schedule, construction approval or physical validation record**. Required physical functions below remain **unverified** in the committed baseline. Required instrumentation is distinct from optional diagnostics, and required functions may use an alternative only after a reviewed equivalence/failure analysis.

Before enabling a real interface, its assembly owner must commit an interface revision naming endpoints, part/revision, supply and voltage/isolation, connector/conductors/GPIO where applicable, polarity, boot/reset state, valid range/units/frame, debounce/freshness, cable/open/short/stuck failure detection, response bounds, protection/isolation and tests. The configuration must reference that revision and the evidence for its exact test/operating stage. Reserved wire pairs and BOM entries are not proof of a completed interface. No new pins or circuits are allocated here.

## Evidence gates

| Gate | Required record and meaning |
| --- | --- |
| D — design/source | Reviewed hazard/interface/configuration revision, chosen limits and acceptance procedure; source/contract checks for any implementation. Merging this register assigns requirements but does not complete electrical/mechanical design review. |
| S — simulation | Deterministic fixtures for normal, missing, stale, contradictory and interrupted behavior, with expected invariants. Only verifies the declared software/model. |
| B — bench/HIL | Approved secured rig or controlled substitute; exact actual target/wiring revisions, calibrated instrumentation, fault injection and measured response. Logical HIL outputs do not establish loaded mechanical stopping. |
| F — secured frame | Accepted component prerequisites, controlled four-line load, exclusion zone, measured forces/clearances/stopping and recovery under frame conditions. |
| I — installed | As-built site/configuration and measured operating envelope, field cable behavior, access/weather/clearance, maintenance and power-loss acceptance. |
| Q — qualified review | Applicable electrical, structural and physical-safety review, accepted residual risk, recovery and inspection procedures for the intended installation. Source authorship is not this review. |

Gates are cumulative only for applicable prerequisites: B may be authorized for an isolated rig before F/I/Q installation acceptance. Each B/F test still needs competent review of its own hazards and procedure. Software mocks cannot pass B, and a real board with substituted inputs cannot validate absent sensors, restraint or loaded stopping. Later-stage authorization fails on missing, failed or inapplicable evidence unless the reviewer explicitly approves a bounded alternative for that stage. [#79](https://github.com/gredice/arbi/issues/79) owns the eventual release evidence index; the current physical gates are pending.

## Optional debug signals

| Diagnostic | Owning interface and present status | Boundary |
| --- | --- | --- |
| Exported driver encoder counts/following error or added drum-angle sensing | Winch → reviewed adapter; encoder currently driver-local; no accepted Pico measurement interface | May improve diagnosis/calibration, but shaft angle alone is not line tension or global pod pose. Catalog AS5600 entry does not establish a fitted/tested input. |
| Motor current waveform, IMU/attitude, vibration or extra environmental sensors | Relevant winch/pod/site instrumentation → tagged diagnostic stream; not established | Optional until accepted as a required safety input through D and its physical gates; do not infer force, clearance or acceptable weather from an unvalidated proxy. |
| CPU load, memory, RSSI, raw scopes and verbose logs | Edge/pod/Pico software or external instruments; expose only supported values | Debug evidence cannot clear a physical gate. Rate-limit/bound diagnostics so they cannot starve protection, control or local storage. |

Both UI modes must show source/age/quality and unavailable capability reasons. Optional diagnostic absence must not invent a fault, while absence of a prerequisite in LS-01–LS-19 must block its affected capability. Recording remains deferred and disabled; viewing/capture, usage accounting and durable audit are separately owned by the software program. Media, updates, cellular-budget exhaustion and failed audit upload cannot inhibit a local emergency response.

## Fault-injection coverage and recovery gates

| Scenario | Required locally observed behavior | Owners, IDs and minimum evidence |
| --- | --- | --- |
| Cloud/browser/WAN outage, duplicate or delayed/reconnected command | Expire manual authority; do not replay. Approved autonomous work follows only its accepted local continuation/abort policy; no cloud acknowledgement for stop | Edge/Pico/pod, LS-09; S plus B actual disconnect; F/I mechanical response |
| Edge crash, local-link failure, MCU scheduler stall/watchdog or pod reset | Each endpoint enforces own bounds. Independent path survives normal-control failure; boot/recovery remains inhibited | Cabinet/Pico/pod, LS-03/06/08/09/19; S/B measured timing; F/I restraint/stop |
| Single driver alarm, missing driver power, encoder loop failure, cable/line break, slack, jam or overload | Latch fault, inhibit coordinated work, use reviewed load-dependent stop/restraint; no blind return-home/homing | Winch/line/cabinet, LS-03/04/10/11; B safe fault substitutes; F/I controlled loaded tests and Q |
| Home/limit/dock input open/short/stuck/bouncing or disagreement | Detect or prevent dangerous undetected failure through reviewed diagnostics/independence; never assert referenced/parked/update-safe from ambiguous data | Winch/dock/cabinet, LS-05/06/16/17; S/B; F/I capture/reference validation |
| Brownout, one rail lost, total power loss, restart during update | No uncommanded output or lease/job resurrection; preserve accepted pod support/line clearance; reconcile references and recover under procedure | Cabinet/winch/dock/edge/pod, LS-08/12/18/19; B then F/I/Q interruption/clearance acceptance |
| Unknown/adverse weather, person entry, missing guard or unavailable dock | Reject dependent work; apply reviewed stop/hold/restraint or controlled recovery for that state; no automatic low maintenance position | Site/edge/dock, LS-14/15/16/18; S policy tests; F/I physical access/weather/failed-dock procedure and Q |

Recovery authorization must name the fault, inspected configuration, valid references/observations, released restraint/isolation conditions, bounded next action and reviewer/operator. It cannot be a generic remote clear-fault. Commit records under the [commissioning record requirements](../operations/prototype-and-commissioning.md#test-record-minimum), with LS IDs, measured detection/response times, raw traces, limits, failures and stage-specific result. Current ownership/follow-ups are recorded in [ADR-0006](../decisions/0006-local-safety-authority-and-instrumentation.md#evidence-and-follow-up-ownership).
